# 작은 바다 · 따뜻한 3D 월드 개편

작성일: **2026년 11월 27일, 한국 시간(KST)**  
상태: 구현 통합·실제 WebGL 브라우저 검증 완료. 웹/토스 최종 빌드·배포 결과는 제출물에서 확인한다. 최종 배포 버전·커밋·검사 합계는 제출물의 `build-info.json`과 CI 결과에 기록한다.

## 1. 목표와 적용 원칙

바다·해변·섬·사람·배·불멍을 하나의 부드러운 3D 디오라마로 연결한다. 둥근 형태, 크림색과 라벤더의 사람 캐릭터, 청록색 물, 자연스러운 잎의 층위와 따뜻한 조명을 서비스 고유 자산으로 구성한다. 배에 탔을 때만 재질이나 캐릭터의 품질이 달라지지 않도록 같은 모델과 조명 기준을 모든 행동에서 사용한다.

Blender는 사람과 환경 소품의 형태·재질을 만드는 도구다. 웹의 카메라·지형·물결·불꽃·행동 모션은 Three.js가 실시간으로 표현한다. Blender의 정지 미리보기와 게임 화면은 사용하는 카메라·조명·렌더링 비용이 다르므로, 출시 품질은 실제 플레이 화면을 기준으로 검토한다.

기존 위치·이동·공유 상태·수집·편지·낚시·요리·겨울 장비·저장 기록을 유지하며, 그림을 그리는 층을 교체한다. 별도의 사용자 데이터 이전이나 서버 데이터베이스 초기화는 필요하지 않다.

## 3. Blender 자산과 재생성

현재 두 GLB의 합계는 **2,189,572 bytes(약 2.09 MiB)** 다. 수중 생물·일부 장비·장식은 런타임 기하로 만들어 별도 GLB가 없다.

| 자산 | 크기 | 삼각형 | 주요 내용 |
| --- | ---: | ---: | --- |
| `public/models/cozy-character.glb` | 982,392 bytes | 34,940 | 사람 모델, 23개 메시 노드, 3개 재질, 독립 관절 그룹과 선택형 모자·음식·낚싯대 |
| `public/models/cozy-world.glb` | 1,207,180 bytes | 36,895 | 야자수·활엽수·침엽수·바위·모닥불·등불·풀과 꽃·배·텐트·종이배 10종 |

SHA-256은 각 manifest와 실제 파일을 함께 확인했다.

```text
cozy-character.glb
b4b75a6e146c2262cdba0f1a68422ee0c8781461c215c35eeb357c042d9f5165

cozy-world.glb
3806107c07a1f54fe437fbcfbb3cccc6d97bdb5d0918ea5d905de2bafaa1c655
```

원본 및 메타데이터:

- [캐릭터 생성 스크립트](../../scripts/blender/build_cozy_character.py), [캐릭터 manifest](../../public/models/cozy-character-manifest.json)
- [환경 생성 스크립트](../../scripts/blender/build_cozy_world.py), [환경 manifest](../../public/models/cozy-world-manifest.json)
- 편집 원본: `/workspace/outputs/little-sea-cozy-3d/cozy-character.blend`, `cozy-world.blend`
- Blender 4.3.2로 작성했다. GLB는 Three.js 기준 **+Y가 위, +Z가 앞**, 발 또는 소품의 지면 기준점을 원점으로 사용한다.

저장소 루트에서 재생성한다.

```sh
blender --background --threads 4 --python scripts/blender/build_cozy_character.py
blender --background --threads 4 --python scripts/blender/build_cozy_world.py
sha256sum public/models/cozy-character.glb public/models/cozy-world.glb
```

Blender 미리보기의 바닥·카메라·스튜디오 조명은 게임 GLB에 포함하지 않는다. 재생성 후 manifest의 크기·해시와 관련 자산 검사를 갱신한다. 캐릭터는 고정 색을 정규화된 vertex color로 묶고 셔츠 색을 별도 재질로 유지한다. 외부 텍스처와 추가 압축 디코더를 요구하지 않는다.

## 4. 렌더링 경계와 좌표 정합

[CozyWorld](../../components/cozy-world.tsx)가 게임 전체의 Three.js 캔버스와 조명을 소유한다. `SeaGame`의 카메라·로컬 사람·접속자·공유 배·날씨·모닥불 상태를 받고, `BeachPlayer`가 가진 월드 영역 안에서 그린다. 입력과 게임 규칙은 기존 컴포넌트가 처리한다.

기존 게임은 표준 PerspectiveCamera와 다른 `projectSea/projectMap` 렌즈를 사용한다. 일반 카메라로 모델만 그리면 종이배, 앉는 자리, 이동 원, 탑승 버튼과 실제 3D 장면이 어긋난다. [cozy-projection.ts](../../components/cozy-projection.ts)는 기존 `boatProjectionGLSL`을 모든 게임 메시의 투영에 적용해 지면·이름·버튼·선택 위치를 일치시킨다.

- 인스턴싱에도 `instanceMatrix`를 포함한 실제 월드 좌표를 사용한다.
- 기존 +Z 전방 렌즈와 Three.js의 기본 카메라는 삼각형 방향 기준이 달라, 런타임에서 winding을 한 번 보정한다. 정점 위치와 작성된 바깥쪽 법선은 보존한다.
- 같은 캐시 재질을 게임 재진입 때 다시 사용해도 GLSL을 중복 삽입하지 않도록 원본 shader hook을 보관한다.
- 기존 렌즈에서 높이가 눌려 보이는 문제는 **지면에 놓인 모델의 로컬 Y 비율 2배**로 보정한다. 캐릭터·나무·소품·배·불꽃에 적용하고, 이동 규칙이 사용하는 지형 높이와 발의 지면 기준점은 유지한다.
- 나무·바위 위 눈은 원래 지면 높이를 보관해, 그 위에 놓인 눈의 높이만 같은 비율로 보정한다.

종이배·그늘막·선물·보물상자·수중 발견물의 기존 DOM 버튼은 남는다. 준비된 3D 모델이 보일 때만 기존 그림을 숨겨 클릭·포커스·스크린리더·획득 로직을 유지한다. 이동 목적지 원과 사람 이름도 그대로 사용한다.

## 5. 지형·움직임·세부 표현

[cozy-landscape.ts](../../components/cozy-landscape.ts)는 본토와 여섯 섬을 기존 `terrainHeight()`에서 생성한다. 본토는 긴 해변 이동을 따라가면서 같은 해안선을 다시 계산한다. 식물은 고정 seed로 배치하고, 불멍 자리·주요 길과 시작 지점 가운데 이동 공간을 비운다. 시작 카메라 앞에는 작은 풀·꽃 군집을 추가해 가까운 풍경에도 볼거리를 둔다.

동일 종류의 나무·풀·바위는 Blender 메시를 재질별로 합쳐 인스턴싱한다. 먼 나무는 단순한 숲 실루엣으로 바꾸고, 시점 뒤·화면 밖 장식은 기존 렌즈와 넓은 잎의 여유 범위를 고려해 걸러낸다. 지도 시점에서는 이 화면 경계 생략을 사용하지 않는다. 카메라 회전·렌즈·화면 크기 변경 시 표시 대상을 갱신한다.

사람의 포즈는 [cozy-character-rig.ts](../../components/cozy-character-rig.ts)가 담당한다. 관절의 quaternion 보간, 눈 깜빡임과 작은 호흡, 걸음과 팔의 교차, 수영·앉기·먹기·낚시 자세를 연결한다. 노젓기는 공통 손잡이 궤적을 손과 노에 적용한다. 배 위에서도 같은 모델·옷 색·모자를 사용하며, 배의 보간 시계를 카메라·선체·좌석과 공유한다.

물결은 [cozy-ocean.ts](../../components/cozy-ocean.ts)의 동일한 높이 함수를 배와 수영에도 사용한다. 바다·날씨의 변화는 색과 광량을 서서히 보간한다. 불꽃·불티·오로라, 수중 해파리 촉수·물고기 꼬리, 작은 물결은 각각 가벼운 메시나 shader 동작으로 표현한다. `prefers-reduced-motion`에서는 반복 동작과 장식 흔들림을 줄이거나 멈춘다.

## 6. 성능 단계와 대체 화면

| 단계 | 동작 |
| --- | --- |
| 기본 `soft-detail` | DPR 최대 1.5, 목표 픽셀 예산 약 1.45M, PCF 그림자와 세부 장식 사용 |
| `balanced` | 저메모리·낮은 CPU 동시성·데이터 절약 설정 또는 지속적으로 낮은 프레임에서 전환. DPR 최대 1, 목표 픽셀 예산 약 0.72M, 실시간 그림자를 줄이고 간단한 접지 그림자 유지 |
| WebGL/자산 실패 | 새 월드의 준비 완료 전에는 기존 바다·지형·사람 표현을 유지. 자산 실패나 context loss 시 대체 표현으로 복귀 |

픽셀 예산은 최소 DPR 0.6과 화면 크기에도 영향을 받는다. 60/30fps 수준의 렌더 스케줄 제한은 실기기 성능 측정값을 의미하지 않는다. 브라우저가 숨겨지면 새 3D 프레임을 그리지 않는다. 게임에서 휴식으로 이동하거나 화면이 해제되면 RAF·observer·재질·기하·렌더러 자원을 정리한다.

같은 캐릭터 GLB는 한 번 받아 템플릿 기하를 공유하고, 각 사람의 재질·포즈는 독립시킨다. 멀거나 떠난 원격 사람의 인스턴스를 재사용한다. 지형과 장식은 카메라·거리 기준으로 범위를 제한한다. 모델을 통째로 여러 번 다운로드하거나 나무마다 많은 독립 draw call을 만드는 구조를 피한다.

**실제 iOS/Android 기기의 FPS·발열·배터리·장시간 메모리 사용은 아직 검증하지 않았다.** 현재 브라우저 검증은 소프트웨어 WebGL을 포함한 기능·시각 검증이다. 이 결과를 휴대폰의 FPS로 환산하지 않는다. 토스 앱에서의 터치·성능·백그라운드 정책 확인도 출시 전 별도 단계다. 기존 ASMR 화면 잠금 재생의 실기기 검증 경계도 유지한다.

## 7. 확인 항목과 현재 상태

아래 자동 검사는 실제 GLB를 파싱하거나 실행 가능한 기하·포즈·투영을 검사한다.

- `tests/cozy-character.test.mjs`: 실제 캐릭터 GLB, 명명된 관절, 색상 데이터와 행동 포즈.
- `tests/cozy-projection.test.mjs`: winding 1회 보정, 재진입 shader 중복 방지, 픽셀 예산, 방향 보간, 공통 노 손잡이 궤적.
- `tests/cozy-ocean.test.mjs`: 물결 범위·연속성, 근경/원경 메시의 연결, 계절·날씨·해제와 자원 정리.
- `tests/cozy-landscape.test.mjs`: 게임 지형·해안선 일치, 인스턴싱 예산, 원근/지도 시점과 회전 culling, Y 보정, 눈 덮개·복구, 긴 해변 이동.
- `tests/cozy-underwater.test.mjs`, `tests/cozy-fishing.test.mjs`: 수중 표현과 발견물, 낚싯줄·찌 등 행동 표현.
- 기존 입장·공유·보안·이동·낚시·편지·수면·겨울·토스 자산 검사를 함께 유지한다.

`tests/browser/sea-cozy.cjs`와 `sea-cozy-activities.cjs`는 실제 WebGL에서 낮/밤/눈/지도, 키보드·탭 이동과 목적지 원, 반복 게임↔ASMR 전환, 대체 화면, 배의 좌석·항해·하선·잠수, 불멍 활동을 확인하는 경로다. 작성 시점에는 최종 활동 회귀와 제출 빌드를 진행 중이다. 자동 검사 전체 합계·모든 활동의 최종 통과 여부·CI와 배포 식별자는 최종 검증 결과로 확정한다.

스크린샷이 만들어졌다는 사실만으로 전체 회귀 완료를 의미하지 않는다. 출력 폴더의 QA JSON에서 `completed`와 오류 목록을 함께 확인한다. Blender 캐릭터·소품 미리보기는 자산 검토용, `qa-cozy-*.png`와 `cozy-boat-*.png` 등은 실제 브라우저 장면 검토용이다.

## 8. 후속 정교화 우선순위

1. 실제 저·중·고사양 휴대폰에서 장시간 이동·입장/퇴장·게임/휴식 전환과 메모리를 측정해 장식 범위·해상도·그림자 기준을 조정한다.
2. 머리·손·노·좌석의 접촉과 회전 중 걸음, 수영·낚시·음식 포즈의 전환을 실 플레이 화면으로 더 다듬는다.
3. Blender에서 만든 작은 재질 atlas나 AO를 검토해 천·나무·잎의 표면감을 더한다. 초기 전송량과 모바일 텍스처 메모리 예산을 먼저 정한다.
4. 아이템별 외형 변주, 시점 근처 식물의 가림 완화, 물과 조명의 미세 표현을 같은 스타일 안에서 확장한다.

이번 개편의 기준은 모델 한 개의 정지 렌더보다, 사용자가 계속 움직이고 쉬는 동안 같은 재질·비율·빛과 안정된 조작을 유지하는 것이다.
