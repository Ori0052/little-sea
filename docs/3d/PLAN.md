# 나의 작은 바다 3D 전환 기획

2026년 11월 9일. 기존 v73의 기능·권한·휴식 경험을 보존하면서 Blender 자산과 Three.js 장면을 검증한다. 이번 산출물은 별도 /3d-lab에서 확인하는 첫 시제품이다. 기존 실시간 게임의 그래픽을 바로 교체하지 않는다.

## 단계와 승인 기준

| 단계 | 구현 범위 | 완료 기준 |
| --- | --- | --- |
| 1 배 단독 | Blender로 선체·바닥·벤치·노 제작, GLB 내보내기, 회전·확대 | 모델 로딩·형태·가림 관계·오류 대체 화면 확인 |
| 2 탑승과 노 | 1~6명 좌석, 첫 좌석 선장 표시, 한 명당 노 하나와 팔 움직임 | 최대 인원·좌석 간격·노 1~6개·좌우 동작 확인 |
| 3 바다와 조명 | 같은 3D 장면의 수면·배·조명, 낮·밤 전환 | 자연스러운 가림·수면 높이·색감, 모바일 프레임 측정 |
| 4 섬으로 확대 | 작은 섬·야자수·텐트의 시제품 | 배와 섬 크기·조명·카메라를 함께 검토 |

## 그래픽 기준

승인된 크림·목재·푸른 배색과 부드러운 입체감을 사용한다. 실사 물 시뮬레이션 대신 가벼운 수면 셰이더를 쓴다. Blender 원본은 재생성 스크립트로 관리하며 GLB 모델을 웹에 제공한다. 최종 아트 확정 전 시제품임을 표시한다.

## 기술과 기존 기능 연결

Blender는 모델·재질 제작, Three.js는 로딩·조명·수면·카메라·애니메이션을 담당한다. 기존 boatCapacity와 boatSeatPosition의 최대 인원·좌석 좌표 규칙을 재사용한다. 테스트 인원은 로컬 시뮬레이션이며 서버 접속 수에 포함하지 않는다. 실제 선장 판정·탑승 검증은 기존 서버가 계속 담당한다.

모델의 노와 팔은 이름 있는 피벗을 통해 동기화한다. 노 젓기는 Three.js에서 절차적으로 구동하며 Blender에서 구운 애니메이션 클립이라고 표현하지 않는다. 모델과 기존 SVG를 별도 깊이 버퍼로 겹치는 방식은 최종 탑승 표현에 사용하지 않는다.

## 성능과 접근성

픽셀 비율은 최대 1.5로 제한하고 화면 크기에 따라 조정한다. 화면 숨김·정지 시 렌더링을 멈추고 자원을 정리한다. WebGL 불가·GLB 실패는 대체 안내를 제공한다. 자동 카메라 회전은 사용하지 않으며 움직임 줄이기 설정에서는 노·물결의 자동 동작을 줄인다. 토스 실기기 성능·발열·배터리·로딩을 확인한 뒤 본편 교체 여부를 결정한다.

## 이번 검증과 이후 과제

이번에는 네 단계를 한 장면에서 순차 확인할 수 있도록 구현한다. 브라우저의 실제 WebGL 렌더링과 모델 노드·좌석·화면 전환을 검증한다. 물리적인 토스 기기와 실시간 다중 사용자 연결은 별도다. 본편 적용 전에는 공유 카메라·좌표 연결, 충돌·정박·보상·모바일 터치 회귀 검증이 필요하다.

## 탑승과 거리에 따른 품질 전환

배에 탔을 때 가까이 보이는 캐릭터만 상세 모델로 표시한다. 탑승 전 또는 멀리서는 같은 비율·색상의 가벼운 모델을 유지한다. 접근 중 상세 자산을 준비하고 완료 전에는 기본 모델을 계속 표시한다. 전환 경계는 진입 4.5, 이탈 6의 장면 거리로 구분하여 경계에서 반복 교체되지 않게 한다. 이 값은 게임의 실제 미터 안내가 아닌 테스트 장면의 좌표 단위다.

자동 모드는 저메모리·저병렬 처리·데이터 절약 조건 또는 지속적인 낮은 프레임에서 기본 표현을 유지한다. 디테일 우선은 사용자 선택이며 탑승·거리 조건은 그대로 적용한다. 상세 자산 실패는 기본 화면 유지와 명시적 재시도로 처리한다. 이 구조는 /3d-lab의 테스트 탑승에서 먼저 적용하며, 본편 서버의 실제 탑승 상태 연결은 후속 통합이다.

## 웹 본편 통합 — 2026-11-09

본편 PartyBoat에서 서버가 확정한 BoatSnapshot과 기존 보간 좌표를 받아 3D 배를 그린다. 좌석·선장 권한·탑승·항해·정박·내리기 요청은 기존 API를 유지한다. 기존 바다의 투영식을 3D 정점에 적용하여 바다와 SVG 섬의 위치를 맞춘다. 본편의 섬·육상 캐릭터 전체가 3D로 교체되는 범위는 아니다.

근처에서 기본 모델을 지연 로딩하고 탑승 중 가까운 시점에서만 상세 캐릭터를 사용한다. 저사양 판정 또는 지속적인 낮은 프레임에서는 기본 모델을 유지한다. 성공적으로 그리기 전에는 기존 SVG 배를 표시하며 기본 모델 실패·WebGL 불가·컨텍스트 손실에도 이를 복원한다. 상세 모델만 실패하면 기본 3D를 유지한다. 모델별 옷 재질을 복제하여 승객마다 다른 색을 유지하고 모자·장착 왕관과 이름을 연결한다. 왕관은 기존 아틀라스의 잘라낸 그래픽이며 별도 입체 왕관 모델은 아니다.

탑승 카메라는 배 뒤 6.5, 눈높이 1.8, 화면 확장 1.0으로 조정한다. 자동 회전은 하지 않는다. 지도/수평선 전환과 하단 항해 버튼은 기존 조작을 유지한다. 물리 토스 기기의 발열·프레임과 실제 다인 동시 접속은 출시 전 별도 확인한다.

## 기본 시점·스타일 검토 및 항해 피드백 — 2026-11-10

새 그래픽은 /boat-preview에서 배 한 척·캐릭터 한 명으로 먼저 검토한다. 일반 PerspectiveCamera를 사용하고 캐릭터 얼굴과 내부 좌석이 보이는 기본 사선 시점을 제공한다. 옆/뒤 사선도 선택할 수 있다. 밝은 나무, 따뜻한 아이보리, 차분한 청회색 테두리와 기존 복숭아 피부·라벤더 옷을 맞춘다. 연속된 둥근 테두리와 수면의 선체 내부 제외 처리를 적용한다. 이는 전체 월드가 아닌 고정된 배의 아트 검토 장면이며 실제 항해 연결·본편 그래픽 교체는 사용자 검토 후 진행한다.

별도로 기존 본편의 조작 문제를 고친다. 배와 추적 카메라는 같은 단조 시계로 매 프레임 위치를 계산한다. 새 서버 응답의 오차는 약 180ms로 보정하며 정박/도착은 서버 경로를 따른다. 정상 기기는 최대 약 60fps, 저사양은 기존 약 30fps로 제한한다. React UI 갱신과 별도로 모델을 샘플링한다. 탑승 중 드래그가 걷기용 카메라 거리로 순간 이동하지 않도록 한다.

항해 요청 직후 짧은 목적지 원을 표시하고, 서버가 수락한 목적지는 항해 중 계속 표시한다. 선장과 승객 모두 볼 수 있으며 정박·도착 시 해제한다. 거리/목적지 문구나 추가 버튼은 만들지 않는다. 수평선 근처의 정상 투영점도 잘못 숨기지 않도록 원의 표시 조건을 수정한다.

## 본편 기존 그래픽 복구 — 2026-11-10

사용자 검토에 따라 본편의 3D 배·캐릭터 연결을 해제하고 기존 RowingBoatArt와 LittlePerson으로 복구한다. 탑승 카메라도 3D 적용 전 거리 8.5·눈높이 2.6·화면 확장 1.15로 되돌린다. 서버 탑승·선장·항해 상태와 최근의 목적지 원, 공통 이동 시계, 드래그 거리 보정은 유지한다. 본편은 GLB 자산을 요청하지 않는다. /boat-preview와 /3d-lab은 비교용 실험 화면으로 보관하며 본편의 확정 스타일이 아니다. 후속 시안은 배 단독이 아닌 바다·섬·배·캐릭터·종이배가 함께 있는 장면으로 검토한다.
