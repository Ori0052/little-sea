# 3D 시제품 제작과 검증 결과

2026년 11월 9일. /3d-lab에서 배 단독·탑승·바다·섬을 단계별로 확인하는 첫 시제품이다. 기존 / 본편과 서버 권한은 변경하지 않았다.

## 제작물

- scripts/blender/build_sea_boat.py: Blender 4.3에서 모델·재질·좌석·노 피벗·섬을 생성하고 GLB 내보내기.
- scripts/blender/sea-boat.blend: 편집 가능한 압축 Blender 원본.
- public/models/sea-boat.glb: 약 702 KiB, 외부 텍스처 없는 웹 자산.
- components/boat-3d-rig.ts: 기존 BoatSnapshot·boatSeatPosition 규칙과 연결되는 표현 어댑터.
- /3d-lab: 4단계, 1~6명, 노 젓기·정지, 낮·밤, 드래그·확대·시점 초기화.

팔과 노는 Three.js에서 같은 주기로 구동한다. 손잡이의 완전한 IK, 구운 애니메이션 클립, 실제 다중 사용자 동기화는 이번 완료 범위가 아니다. 선장 고리는 테스트의 첫 좌석에 표시하며 실제 선장 권한은 기존 서버 기준을 유지한다.

## 검증

실제 GLB를 읽는 단위 검사 3개로 Blender 생성자·필수 노드·1 MiB 자산 한도·6개 좌석·한 사람당 노 하나·정지·움직임 줄이기를 확인했다. 기존 26개 검사와 웹·토스 빌드를 함께 실행한다.

Chromium의 실제 WebGL을 SwiftShader로 구동해 모델 로딩, 인원 1~6명, 4단계, 낮·밤, 정지, 390px 모바일 화면을 확인했다. WebGL 비활성·GLB 로딩 실패·재시도도 별도 점검한다. 이 결과를 토스의 물리 기기 성능으로 일반화하지 않는다.

첫 렌더에서 물결의 격자 무늬·수면 아래 섬·과한 조명·많은 그리기 호출을 발견했다. 수면 셰이더와 섬 높이·조명을 조정하고 부모·재질별 메시 병합으로 수정했다. 6명과 섬을 표시하는 장면의 draw call은 346에서 69로 줄었다. 소프트웨어 렌더러의 프레임은 약 10~14 FPS로, 실제 모바일 GPU 성능의 측정값이 아니다.

노 젓기를 정지하거나 움직임 줄이기를 설정하면 화면 변경 시에만 다시 그린다. 화면 숨김 동안 렌더링을 건너뛰고 이탈 시 geometry·material·renderer·controls 자원을 정리한다.

## 재현

`blender --background --python scripts/blender/build_sea_boat.py -- public/models/sea-boat.glb`

`node tests/boat-3d.test.mjs`

개발 서버 실행 후 `PLAYWRIGHT_MODULE=/path/to/playwright node tests/browser/sea-3d-flow.cjs`. 출력 폴더는 SEA_TEST_OUTPUT, 주소는 SEA_TEST_URL, Chromium 경로는 CHROMIUM_PATH로 지정한다.

4. 토스 실제 기기의 로딩·메모리·발열·배터리·프레임 검증.

기존 게임을 전부 3D로 전환했거나 토스 실기기 검증이 끝났다고 표시하지 않는다.

## 둥근 캐릭터 수정

2026년 11월 9일. 머리를 더 크고 둥글게 하고 몸통·소매·손·다리·발을 통통하고 짧게 조정했다. 분홍 볼과 작은 미소를 추가하고 모자도 둥근 비례에 맞췄다. 기존 좌석·노 피벗은 유지한다. 모델은 약 895 KiB로 1 MiB 한도 안이다. 6명 탑승 간격과 노 움직임을 실제 WebGL 화면에서 재확인한다. 본편의 SVG 캐릭터는 이 수정 범위가 아니다.

## 승인된 밤톨머리 시안 반영

2026년 11월 9일. 사용자가 확정한 사람형 밤톨머리 시안을 3D 테스트 모델에 반영했다. 큰 둥근 얼굴과 노출된 귀, 짧은 곡선 앞머리, 작은 삐침, 부드러운 피부색과 무광 재질을 적용했다. 앞머리는 연결된 메시로 구성하고 작은 미소를 하나의 곡선 메시로 정리했다. 기본 상태에서는 머리가 보이도록 모자를 숨기며, 모자 쓰기·벗기와 캐릭터 가까이 보기를 제공한다. 모자와 머리카락은 각각 이름 있는 노드로 유지한다.

GLB는 996272 bytes로 기존 1 MiB 한도 안이다. 실제 GLB 검사에 6개 모자 전환·머리 노드 보존을 추가했다. 확대 화면·모자 착용·벗기·6명 좌석·모바일 배치를 WebGL에서 검증한다. 기존 본편 SVG 캐릭터와 실시간 동승 전환은 여전히 별도 통합 단계다.

머리와 얼굴의 곡면 해상도를 높이고 동일한 형상의 메시를 캐릭터 사이에서 공유해 파일 크기를 유지했다.

## 시안 색감 복원

2026년 11월 9일. 시안과 실제 렌더링의 색감 차이에 대한 피드백을 반영했다. 작업 기준색은 복숭아 피부 #FFDABE, 밀크 브라운 머리 #96654F, 파스텔 라벤더 옷 #C9B5E3, 따뜻한 아이보리 바지·신발 #F7EEDF다. 다른 탑승자 옷도 낮은 채도의 밝은 팔레트로 조정했다.

Blender 재질에 정확한 sRGB 변환을 적용하고 Three.js의 톤 매핑을 Neutral로 변경했다. 노란 주광과 어두운 하부 환경광을 중립적인 주광·밝은 하부광·부드러운 보조광으로 조정했다. 과한 주변광으로 평평해지는 현상은 실제 확대 화면을 보며 조정했다. 모델 URL에 팔레트 버전을 붙여 기존 브라우저 캐시와 구분했다.

동일한 가까이 보기에서 수정 전후 스크린샷을 확인했다. 이번 수정은 재질과 조명·옷 색을 중심으로 하며 시안 수준의 세부 모델링이 모두 완료됐다는 의미는 아니다. 실제 토스 기기와 화면별 색 표현은 별도 확인 대상이다.

## 노 젓기 손과 팔 접점 수정

손이 어색하다는 피드백에 따라 팔을 일괄 회전하던 방식을 제거했다. 각 노에 두 개의 파지점을 정의하고 노의 현재 변환에서 손 위치를 계산한다. 어깨·팔꿈치·손목은 두 관절 IK로 풀어 서로 다른 양손이 같은 손잡이를 잡게 했다. 상완·전완·팔꿈치·손을 별도 노드로 만들고 팔이 가슴을 가로지르는 한 덩어리처럼 보이지 않게 분리했다. 노의 높이와 축도 좌석·난간에 맞춰 조정했다.

방향·이동·시간·좌석이 바뀌어도 손이 파지점에 붙는지 검사하고, 실제 내보낸 노 메시 표면과 손이 닿는지도 검사한다. 기존 노 1~6개·모자·색감·정지·움직임 줄이기 동작을 유지한다. 손가락별 쥐기나 실제 토스 기기 검증까지 완료한 것은 아니다.

## 탑승 근접 상세 모델 전환

Blender에서 같은 비율·재질·좌석·파지점의 두 자산을 생성한다. 기본 배 자산은 약 880 KiB이며, 별도 상세 자산은 캐릭터와 동작 피벗만 포함한 약 1.6 MiB다. 상세 자산에는 섬과 배 메시를 중복 포함하지 않는다. 가까운 캐릭터의 머리·머리카락·몸 곡면 해상도를 높이는 전환이며 시안 수준의 전체 모델링 완성을 의미하지 않는다.

실제 탑승 대신 로컬 테스트 탑승 상태로 동작을 확인한다. 시작 시 상세 자산을 요청하지 않고 접근 시 한 번 미리 불러온다. 탑승·거리 조건이 맞고 로딩이 완료된 캐릭터만 교체한다. 멀어짐·내리기·가볍게 모드·자동 절전에서는 기본 모델을 표시한다. 상세 자산은 현재 방문 동안 캐시하고 페이지 이탈 시 두 모델 자원을 정리한다.

선택 로직과 거리 완충 구간, 낮은 성능 조건, 모델의 색상·손 위치 일치와 상세 폴리곤 증가를 검사한다. 실제 WebGL에서 미리 로딩·전환·내리기·기본 유지·실패 재시도·모바일 배치를 점검한다. 브라우저 테스트의 소프트웨어 렌더링 성능을 실제 토스 기기 성능으로 일반화하지 않는다.

재생성은 기존 기본 모델 명령에 `--detail low`를 붙이고, 상세 모델은 `blender --background --python scripts/blender/build_sea_boat.py -- public/models/sea-characters-high.glb --detail high`로 생성한다. 대응 Blender 원본은 sea-boat.blend와 sea-boat-high.blend로 분리한다. 자동 성능 보호는 낮은 프레임 표본이 네 번 연속 발생했을 때 적용하며 렌더링 픽셀 비율도 1로 낮춘다. 테스트에서 프레임을 늦춰 이 전환을 재현했다.

## 웹 본편 연결 — 2026-11-09

- 실제 본편 컴포넌트에 서버 BoatSnapshot·카메라·좌석·탑승 권한과 연결했다. 테스트 페이지 전용 탑승 상태를 본편에 주입하지 않는다.
- 로컬 브라우저 QA는 API 응답을 모의하여 접근 → 탑승 → 항해 → 정박 → 내리기와 지도/수평선, 모바일 390×844 표시를 확인했다. 실제 서버 6인 동시 접속의 증거로 해석하지 않는다.
- 투영 회귀 테스트 2개로 기존 바다/SVG 및 지도 좌표와 높이 보정의 일치를 검증한다. 실제 WebGL 셰이더 컴파일과 화면도 확인했다.
- 소프트웨어 GPU는 자동 저사양 전환이 발생할 수 있다. 실기기 성능·발열·시각 품질에 대한 보증으로 사용하지 않는다.
- 6인 모의 좌석에서 상세 자산 로딩 완료와 상세 캐릭터 6명 표시를 확인했다. 실제 여섯 기기의 접속 시험과 구분한다.

## 기본 장면 검토·항해 피드백 — 2026-11-10

/boat-preview는 기존 모델을 재사용하는 실제 Three.js 화면이며 이미지 시안이 아니다. 원근·배 테두리·미리보기 재질·수면을 함께 조정했다. 기본/옆 사선, 낮/밤, 노 젓기와 모바일 폭을 브라우저에서 확인했다. 기본은 정지 장면이며 노 젓기는 고정 위치에서 미리 보는 절차적 애니메이션이다. 정지 상태에서는 설정·카메라·크기가 바뀔 때만 그린다.

본편은 모의 API를 사용해 항해 목적지 원과 정박 동작을 확인하며, 단조 시계·서버 갱신 보정·숨김 후 복귀에 대한 자동 테스트 3개를 추가한다. 소프트웨어 GPU 검증을 실제 기기의 프레임·발열 보증으로 해석하지 않는다. 새 아트의 본편 적용은 사용자 검토 후 별도 작업이다.
