# 나의 작은 바다 · 앱인토스

등록된 appName은 `little-sea`입니다. 현재 웹사이트의 실제 게임 코드를 공유하는 독립적인 Vite SPA이며, 사이트를 iframe으로 띄우거나 외부 웹으로 이동시키는 구조가 아닙니다.

## 빌드와 파일

저장소 루트 의존성을 먼저 설치한 후 이 디렉터리에서 실행합니다. Node >=22.13.0.

```sh
npm ci
npm run build
npm test
```

`little-sea.ait`가 토스 콘솔 업로드 파일입니다. SDK와 CLI는 공식 `@apps-in-toss/web-framework@3.9.0`을 고정했습니다. 3.x의 `apps-in-toss.config.ts`와 타입 선언에 실제 존재하는 API만 사용합니다. 웹 사이트 배포용 Worker는 이 번들에 포함되지 않습니다. 번들은 100MB 제한 안에서 빌드하며 10종 PNG 부적과 음원을 동봉합니다.

로컬에서는 루트의 `npm run dev`(5173), 여기의 `npm run dev`(5174)를 함께 실행합니다. 5174는 /api를 5173으로 프록시합니다. 브라우저에는 토스 네이티브 브리지가 없으므로 네이티브 저장·공유·뒤로가기의 최종 검증은 콘솔 QR 테스트에서 해야 합니다.

## 적용한 호스트 연결

- 기존 3D 섬·바다·낚시·모닥불·수집·온보딩을 같은 소스에서 빌드합니다.
- `SafeArea.get/subscribe`로 상하좌우 여백을 반영하고, 가로 방향에서도 64px의 5개 버튼 바를 유지합니다.
- `graniteEvent.backEvent`: 열린 모달 → 옷장/굽기/설정 → 낚시 취소 → 펼친 메뉴 순으로 닫습니다. 기본 화면에서는 종료 확인 후 `Screen.close`를 호출합니다. 시작점으로 이동시키지 않습니다.
- `File.saveBase64`로 PNG 저장, `Share.createLink/sendMessage`로 부적 공유, 필요할 때만 `Clipboard.setText`로 링크를 복사합니다. 미지원 버전에서는 저장 성공으로 표시하지 않습니다.
- 공유 링크는 `intoss://little-sea/?amulet=<검증된 부적 ID>`를 기반으로 생성합니다. `Environment.initialURL`의 선물도 복원합니다. QR 테스트의 private origin을 공유하지 않습니다.
- localStorage 기록을 알려진 키에 한해 SDK `Storage`로 보조 저장합니다. QR 테스트와 정식 출시의 보조 저장 공간은 나눴습니다. 브리지 지연은 시작을 무한히 막거나 이후 플레이를 덮어쓰지 않습니다. 웹 기록을 토스로 자동 이관하지 않습니다.
- `User.getAnonymousKey`를 조회해 네이티브 저장소에만 보관합니다. 서버 로그인이나 신원 인증으로 사용하지 않습니다. 기존 익명 방문 UUID 방식은 유지하며 토스 로그인·계정 간 동기화를 추가하지 않았습니다.
- 백그라운드에서 바다·모닥불 소리를 멈추고, 사용자가 켜 둔 소리만 복귀 시 재시도합니다.
- 별도의 외부 웹 이동 버튼을 없애고, 설정에 이용·저장 안내를 넣었습니다.

웹과 토스가 사용하는 공용 서버: `https://little-sea.rhfenrdltkfk.chatgpt.site`.
`lib/sea-origin.ts`는 아래 두 origin에만 게임 API의 CORS를 허용합니다. 쿠키나 자격증명 전달을 사용하지 않으며 다른 origin, 와일드카드, 임의 헤더를 허용하지 않습니다.

- `https://little-sea.apps.tossmini.com`
- `https://little-sea.private-apps.tossmini.com`

웹사이트의 GA4 설정은 유지합니다. 앱인토스 번들은 웹 layout을 사용하지 않으며 GA4·원격 폰트를 포함하지 않습니다. 외부 분석을 토스 버전에 추가하려면 개인정보처리방침 및 해당 플랫폼 정책을 함께 확인해야 합니다.

## 콘솔에서 남은 단계

1. 등록된 `little-sea` 앱의 번들 업로드 화면에 `little-sea.ait`를 올립니다.
2. 콘솔의 컴파일 성공 후 제공되는 QR/테스트 링크를 실제 토스 앱에서 엽니다. Android와 iOS에서 아래 실기기 점검표를 확인합니다.
3. 운영자·문의처·개인정보처리방침 URL, 게임 분류/등급, 앱 소개와 등록 이미지를 콘솔의 현재 요구사항에 맞게 채웁니다. 서비스 안의 이용·저장 안내가 법적 개인정보처리방침을 대체하지는 않습니다.
4. 실기기 확인과 콘솔 필수 정보 확인 후 심사를 요청합니다. 이 작업에서는 콘솔 업로드·심사 요청·토스 내 출시를 실행하지 않았습니다.

### 실기기 점검표

- 첫 접속 안내를 완료/건너뛰면 재실행 후 자동으로 다시 뜨지 않는지
- WebGL 섬·나무가 실제로 표시되는지, 화면 회전 후 버튼이 잘리지 않는지
- Android 시스템 뒤로가기와 상단 뒤로가기가 열린 창부터 닫는지
- 파도·빗소리·모닥불 소리, 사용자 음소거와 앱 전환 후 복귀
- 다른 기기/웹 이용자의 이동, 섬 이동·낚싯줄·입질·잡기·취소·조리 공유
- PNG 저장이 사진/파일에 남는지와, 취소·권한 거부·미지원 버전에서 성공으로 표시하지 않는지
- 링크 공유 → 수신자 토스에서 해당 부적 표시 → 간직하기
- 인터넷 끊김과 복구, 화면 재실행 후 수집 기록 유지

`submission/app-icon-600.png`는 기존 물결 로고를 바탕으로 만든 아이콘 초안입니다. 콘솔이 요구하는 최신 이미지 크기와 여백은 업로드 화면에서 확인해야 합니다.

## 검증 범위와 근거

타입 검사, 공식 CLI의 .ait 생성, 번들 재읽기, origin 격리·PNG·공유 어댑터·뒤로가기·저장 복원 단위 검증 및 Chromium 모바일 UI/실제 WebGL 검증을 수행합니다. 네이티브 호출 계약은 SDK 타입과 mock으로 확인한 것으로, 실제 토스 브리지나 심사 통과 검증은 아닙니다.

공식 게임 출시 체크리스트와 콘솔 운영 안내를 확인했습니다. 실제 토스 앱 테스트, 게임 등급분류와 콘솔 필수 항목 작성은 별도로 필요합니다. 심사 통과를 보장하지 않습니다.

- https://www.npmjs.com/package/@apps-in-toss/web-framework
- https://github.com/toss/apps-in-toss-harness
- https://developers-apps-in-toss.toss.im/checklist/app-game
- https://developers-apps-in-toss.toss.im/documentation/integration/server-api

SDK 버전·appName을 바꾸면 설정, 공유 링크, 서버 origin 허용 목록을 함께 검토해야 합니다. 3.0.x와 3.1+의 origin은 다릅니다. 콘솔 비밀키나 mTLS 인증서는 소스·.ait·정적 자산에 넣지 않습니다.

## 탐험 확장

총 6개 섬: 기존 모닥불·캠핑·먼 작은 섬과 산호섬·안개섬·별빛섬. 새 지형은 기존 WebGL 렌더러를 공유합니다. 세 섬에는 각각 산호의 울림, 별→달→파도 돌문, 등대 탐험 기록이 있습니다. 기존 6종 보물의 ID·소유권은 유지하고 그림과 일부 발견 해역만 변경했습니다.

6인승 배는 선장 포함 여섯 자리이며, `/api/boat`와 공용 D1의 `sea_boat`, `boat_passengers`를 사용합니다. `drizzle/0007_many_firestar.sql`을 서버 배포에 포함해야 합니다. 서버가 좌석·선장·항로·연결 종료 인계를 확인합니다. 선장은 지도에서 바다 중간 지점을 골라 섬을 돌아갈 수 있습니다. 이동 중 하선은 제한합니다. 기존 뗏목은 유지합니다.

광고 그룹이 없으면 광고 요청·광고 버튼 모두 표시하지 않습니다. 실제 콘솔에서 발급받은 리워드 광고 그룹 ID를 빌드 환경의 `VITE_TOSS_REWARDED_AD_GROUP_ID`로 설정하면 공식 전면 광고 SDK 어댑터가 활성화됩니다. 완료 이벤트 후 닫힘이 확인된 경우에만 부적 1장을 주며 10종은 동일 확률입니다. 실제 광고 그룹과 토스 실기기에서의 완료·취소·실패·소리 복귀 검증 전에는 광고 활성 버전을 출시하지 마세요.

## 텐트 쉼터

캠핑 섬의 텐트 입구로 접근하면 작은 실내 쉼터를 열 수 있습니다. 침대에 눕기·일어나기·밖으로 나오기를 제공하며 실내에서는 바깥 이동 입력과 안내를 멈춥니다. 텐트 밖으로 나오면 입구 위치를 유지합니다. Esc 및 토스 뒤로가기는 네이티브 dialog 취소 처리로 방을 닫습니다. 이 실내 휴식은 개인 화면이며 공유 침대 점유 기능은 포함하지 않습니다.

## 함께 타는 나무배 디자인

배는 속이 빈 곡면 선체·크림색 나무 판재 4단·두꺼운 테두리·3열 좌석·양쪽 노를 게임 카메라에 맞춰 투영합니다. 캐릭터와 선체를 깊이 순서로 그려 승선자 중복 및 겹침을 줄였습니다. 승선 중에는 배 중심을 기준으로 넓은 시점에서 봅니다. 정원 6명, 최초 탑승 선장, 선장 항해 권한과 연결 종료 인계 등 서버 규칙은 유지합니다.

## 좌석별 노 젓기

노는 빈 배의 기본 1개에서 시작하여 실제 탑승자 수만큼 표시하며 최대 6개입니다. 각 노는 해당 좌석의 손 위치와 연결되고, 항해 중 노의 회전·들기와 팔·몸 기울기가 함께 움직입니다. 출항 시각과 보정된 서버 시각으로 동작 위상을 계산하여 선장·승객·바깥 관찰자가 같은 항해 동작을 봅니다. 정박 시에는 노와 팔이 휴식 자세로 멈춥니다. 선체는 더 긴 뱃머리, 높은 크림색 판재, 청록색 테두리와 나무 좌석으로 다시 구성했습니다.

## 탑승 창 복구와 미활동 종료

같은 브라우저의 이전 창에 남은 배 좌석은 현재 창에서 멈춘 배 가까이 탑승을 누르면 원래 좌석 그대로 넘겨받습니다. 서버는 현재 창의 접속·거리·정박 상태를 확인하고 좌석 session만 교체합니다. 이전 창의 heartbeat나 pagehide가 새 창의 점유를 갱신하거나 삭제하지 않습니다.

10분 동안 조작(포인터·키보드·휠)이 없으면 30초 전부터 안내하고 접속을 종료합니다. 자리를 해제하고 presence 갱신을 중단하며 게임 입력과 소리를 멈춥니다. 수집 기록은 삭제하지 않습니다. 다시 입장 버튼으로 새 접속을 생성합니다. 백그라운드에서 돌아올 때도 실제 경과 시간을 확인합니다. 로그인 계정이 없는 익명 서비스이므로 계정 로그아웃 대신 접속 종료입니다.

## 배 HUD 간소화

배로 이동하거나 승선한 동안 목적지·남은 거리 안내를 숨깁니다. 선장 안내는 기기에서 처음 선장이 됐을 때 3.5초간만 표시합니다. 인원은 하단바 위 작은 배 아이콘+숫자로 표시합니다. 하단 상황 버튼은 정박 중 내리기, 항해 중 정박하기이며 승객은 항해 중 정박 버튼이 비활성화됩니다. 기존 큰 탑승 안내 바는 제거했습니다. 항해 목적지 선택은 메뉴의 탐험 지도나 바다 터치로 가능합니다.

## 서버 세션·점유 보호 (보안 업데이트)

`drizzle/0008_salty_korvac.sql` 적용이 필수입니다. `/api/session`이 서버 세션 ID와 256비트 비밀 토큰을 발급합니다. 최초 등록 시 브라우저가 복구 비밀을 먼저 저장하고 서버는 해시만 보관합니다. 응답 유실 후에도 같은 비밀로 재시도할 수 있습니다. 기존 visitor UUID와 수집 기록은 유지합니다. 기존 UUID는 첫 보안 등록 이전에는 소유 증명이 없었던 레거시 식별자이며, 첫 등록 후부터 복구 증명을 요구합니다.

모든 게임 변경 API는 세션 ID·visitor·토큰·만료를 확인합니다. 접속 갱신·삭제는 visitor까지 일치해야 합니다. 토큰과 복구 비밀은 서버에 원문으로 저장하지 않으며 공개 presence에 포함하지 않습니다. 토큰은 브라우저 메모리에, 복구 비밀은 이 기기에 저장합니다. 토스 SDK 보조 저장에도 visitor와 복구 비밀을 함께 포함합니다. 세션 유효기간은 6시간이며 정상 이용 중 갱신은 같은 ID를 유지합니다. pagehide/미활동 종료는 해당 세션을 폐기합니다.

기본 제한:
- 같은 네트워크 신규 visitor 6개 / 10분, 세션 발급 요청 30회 / 10분
- 같은 네트워크 현재 접속 visitor 최대 8명
- visitor당 배·그늘막·모닥불 통틀어 자리 1개
- 같은 네트워크 배 좌석 최대 2개, 전체 자리 최대 4개
- 활동 요청 visitor당 40회 / 분, presence 요청 150회 / 분

네트워크는 Cloudflare ingress의 `CF-Connecting-IP`를 해시하여 구분합니다. 운영에서는 이 헤더를 신뢰할 수 있는 Cloudflare ingress가 덮어써야 합니다. 로컬 테스트에서는 합성 헤더로 별도 네트워크를 흉내 냈습니다. IP 제한은 실제 사람 인증이 아니며, VPN/여러 네트워크로 우회될 수 있고 같은 와이파이·통신사 공유 IP 이용자가 한도를 공유합니다. 트래픽을 보며 수치를 조정해야 합니다. 위치 위조 검증과 수집품 서버 무결성은 이번 변경 범위가 아닙니다.

점유 제한은 INSERT/UPDATE SQL 안에서 검사하여 동시에 요청해도 한도를 넘지 않습니다. 접속 없는 자리 예약은 거절합니다. 같은 브라우저 배 복구도 유효한 복구 증명으로 발급된 세션에서만 가능합니다. 레거시 웹 탭은 새로고침해야 하며 예전 .ait는 새 서버 프로토콜과 호환되지 않으므로 새 번들을 콘솔에 업로드해야 합니다. 토스 콘솔 업로드는 이 작업 환경에서 실행하지 않았습니다.

보안 회귀검사: 루트에서 `node tests/sea-session.test.mjs`를 실행합니다. 실제 SQLite에 대해 세션 소유권·만료·요청 한도·공유 점유 조건을 검사합니다. 별도로 로컬 Worker에서 동시 점유, 창 복구, 8명 접속 한도, 종료 토큰 폐기, 6인 탑승과 모바일 미활동 종료를 확인했습니다.
